# 需求规格

## 1. 目标与范围

**现状**：OpenTalk 是浏览器实时语音／文字助手，提供通用 `ConversationAgent`。用户可以连续交流、切换输入模式、查看历史，并继续正常结束的会话。当前没有独立业务模块。

当前使用场景是同一台机器上的可信单用户环境。服务可在本机或 Docker 中运行；不承诺公网服务、多租户、跨设备同步或高可用。工程规范按可维护、可验证、可接续工作制定，不能据此宣称系统已可公开生产部署。

## 2. 用户与功能需求

用户负责输入、授权麦克风和判断回复是否满足意图；维护者负责配置、运行、数据备份与验证。AI 编程助手负责授权范围内的实现和证据，不代替需求负责人决定业务语义。

| ID | 功能与预期结果 | 当前边界 |
| --- | --- | --- |
| FR-01 | 网页文字输入得到逐步出现的回复；不申请麦克风，不为该文字回复启动 TTS | 网页仍连接 LiveKit；Python 文本 CLI 在该用户轮次完成后打印回复 |
| FR-02 | 开启语音后发送麦克风音频，展示识别文本并播放回复；识别、生成、合成使用流式接口 | 需要浏览器权限、可达媒体网络及有效 provider 凭据；短句未必观察到输入输出重叠 |
| FR-03 | 用户在播报期间说话，可以打断旧生成和音频；后续回复处理新输入 | 使用原生 VAD 打断；已开始的工具工作不能靠停止播报自动撤销 |
| FR-04 | 同一会话支持文字／语音切换；Cancel voice 停止音频，原文本生成继续，工具不重新执行 | 关闭语音与“说话打断”是不同操作；当前文字回复中途开启语音不强制补读该回复 |
| FR-05 | 用户与助手字幕分开；识别修订覆盖同一片段，避免显示或存储重复 | UI 可以合并连续用户气泡，持久化仍保留原生消息；UI 不展示系统和工具明细 |
| FR-06 | 会话消息提交后保存；New chat／选择历史先结束当前会话；正常完成后可跨进程接续 | 同逻辑 session ID、新 attempt／房间；failed 不可恢复；关闭页面请求只保证尽力发送 |
| FR-07 | 恢复历史和回复语言偏好，不重放历史工具，不恢复旧音频或运行任务 | 模型仅使用有界历史上下文，不保证记住完整归档；只注册 conversation |
| FR-08 | 中文、英文与混合内容保留原文；明确偏好影响后续模型输出和 TTS | 持久偏好只匹配四种独立中英文指令；任意自然语言偏好解析尚未实现 |
| FR-09 | 难题可执行一次独立高强度分析，提示等待，返回结论后继续默认模型 | 每用户轮次最多一次；分析不带工具；不提供数据库或外部信息访问 |
| FR-10 | 可查看服务状态、会话和历史；CLI 管理命令无需模型调用 | 状态面板检查配置存在及基础服务，不证明付费 provider 有效或媒体可达 |
| FR-11 | 模型、端点、语音与生命周期参数集中配置；支持本地及容器运行 | LLM 兼容端点可配置；ASR／TTS 当前工厂固定 Soniox，换厂商需要适配代码 |

## 3. 质量要求

以下是交付要求；未实现部分在待改进问题中说明。

| ID | 必须满足的要求 | 如何判断 |
| --- | --- | --- |
| NFR-01 一致性 | 同 ID 的消息、事件和请求不能因重试重复产生语义记录；历史和最终 completed 状态在同一会话库事务提交 | 幂等、竞争和事务故障测试；API 音频模式重试差距见 G-04 |
| NFR-02 资源边界 | 对模型上下文、遥测队列、遥测保留和单次会话时长设置上限；关闭流及后台任务 | 配置、取消和资源释放用例；用户历史当前无自动保留上限 |
| NFR-03 隐私与权限 | 凭据只在服务端；token 限定房间；RPC 限定关联参与者；诊断不默认复制敏感内容 | 构建／配置检查和接口测试；归档含对话正文与工具输出；公网鉴权尚未实现 |
| NFR-04 失败可解释 | 不把失败、跳过、超时或配置存在误报为成功；失败持久化、关闭失败不能标为正常可恢复 | 断线、磁盘、provider 和关闭错误测试 |
| NFR-05 性能可测 | 区分轮次结束、首文本、首音频和实际播放；延迟用单调时钟，跨端不直接相减 | 提供测量口径和代表性用例；目前无批准的 p95、并发量或可用性 SLO |
| NFR-06 可维护 | 保持分层和接口，锁定依赖，控制改动范围；代码和文档可由其他工程师接续 | 静态检查、契约测试和文档审查；新增工程门禁尚待接入 |
| NFR-07 部署可复现 | 固定运行环境、保留持久化卷、独立测试数据与可回滚部署步骤 | 锁定安装、构建、重建和备份恢复验收；当前只定义本地部署 |

性能目标、目标用户规模、历史保留／删除策略及公开部署范围需由负责人给出，再转成可量化需求；本文件不自行补定阈值。

## 4. 当前不包含

登录、多租户隔离、电话接入、分布式状态、高可用、供应商自动切换、长期语义记忆和新的业务工具。当前 PDF 模块已提供后台解析、索引准备、dense embedding 和 Qdrant 持久化；尚无 Hybrid Retrieval、层级展开排序、Agent 查询工具或前端文档管理。

## 5. PDF 解析与 RAG 查询业务模块

### 5.1 业务目标与用户用例

当前阶段允许维护者从命令行传入一个本地 PDF，使用 Docling 自动解析，人工检查结构化中间产物，再将可检索节点生成 embedding 并写入全局 Qdrant。后续阶段按数据流增加 Retrieval、Agent 工具和可选的前端文档管理；每一阶段能单独运行和验证，不要求先实现完整端到端架构。

### 5.2 功能与数据要求

| ID | 当前功能与预期结果 | 边界 |
| --- | --- | --- |
| PDF-01 | 命令行接收一个 PDF，执行 OCR、布局、阅读顺序、表格结构、图片描述／分类、公式和代码富化 | 只接受本地 PDF；Docling 模型首次使用可能下载；不调用远程富化服务 |
| PDF-02 | PDF 原件按内容哈希保存在全局文档目录，不与 session、attempt、历史或遥测关联 | 相同内容共用一份原件；文件名只作为 manifest 元数据 |
| PDF-03 | 每次解析生成独立解析版本，保存 manifest、Docling JSON、Markdown、元素清单和非文本资产 | 解析版本表示一次处理结果；允许同一原件有多个版本 |
| PDF-04 | 图片以引用文件和元素裁剪保存；表格保存结构、HTML、CSV和裁剪；公式保存识别文本／LaTeX和裁剪 | 描述是派生信息，不能替代原元素、结构或来源位置 |
| PDF-05 | 元素清单保留 Docling self reference、父子关系、层级、页码、坐标、文本、metadata和annotation | 供人工检查及索引准备使用 |
| IDX-01 | 对一个已完成的解析版本生成独立索引准备 profile，输出与 embedding 模型和数据库无关的层级节点 | profile 目录不可覆盖；重复实验使用新 profile 名称 |
| IDX-02 | 节点包含文档、章节、有界 context 父块、精确文本小块和非文本节点；可检索节点保留前后邻接引用 | 后续 Retrieval 命中小块后可展开父块，或按邻接关系回退 |
| IDX-03 | 图片 caption 和明确的描述／摘要／关键词／主题／实体等语义字段进入可检索文本；模型来源、分类候选、置信度、annotation类型和生成控制token不进入 | 无描述的非文本元素仍保留节点，但不伪造可检索描述；原始资产继续以路径引用 |
| IDX-05 | 索引准备排除 Docling 明确标为 furniture、page_header 或 page_footer 的元素及其结构子元素 | 不根据页边距、跨页重复、图片哈希或分类结果推断页眉页脚，避免误删正文 |
| IDX-04 | 提供结构检查命令，报告父子／邻接错误、块大小、缺失资产、节点数量、页码覆盖及内容样本 | 检查结构与内容准备质量，不代替真实 embedding 与查询评估 |
| EMB-01 | 对 `indexable=true` 且检索文本非空的节点生成本地 dense embedding | 默认 FastEmbed 多语言模型；显式检查 token 上限，不静默截断超限节点 |
| EMB-02 | embedding provider 与向量存储分离，并记录 provider、模型、profile、维度及内容哈希 | 切换模型使用新的 embedding profile 和独立集合，避免混合不同向量空间 |
| VDB-01 | 将向量以稳定 point ID 幂等 upsert 到全局 Qdrant | 向量不进入 session 数据库；重复运行同一 profile 不增加重复 point |
| VDB-02 | point payload 保留精确节点、父块、邻接、章节、页码、来源和非文本资产引用 | Retrieval 可在后续阶段展开父块或回退邻接，并解析图片引用供多模态输入 |
| VDB-03 | 提供带文档／解析／索引 profile 过滤的底层 dense 查询命令 | 只用于本阶段人工评估 embedding 与入库质量；不代表 Hybrid Retrieval 或最终排序 |

### 5.3 质量、安全与验收要求

- 文件大小、页数、单文档处理时间及图像分辨率由公开配置限制。
- 输入在建立文档目录前检查常规文件、非空、大小及 PDF 文件签名；损坏、加密或模型失败由 Docling 错误明确终止。
- 成功与失败解析均保存 manifest；成功不得在缺少核心输出时上报。
- 解析、索引准备和向量化 manifest 是全局文件数据，Docker 使用目录挂载；向量及 payload 保存到全局 Qdrant；两者均不写入会话数据库。
- 本阶段不为数据一致性、迁移或跨存储事务预设复杂机制；是否增强由模块和集成测试结果决定。
