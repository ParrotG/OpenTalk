# OpenTalk 开发计划

## 1. 目标与当前范围

构建用于技术面试准备、学习与验证的浏览器语音 demo。首版使用远端 ASR、LLM 和 TTS，通过语音完成会议室查询、预约、查询预约和取消预约。使用固定 demo 用户与模拟业务数据。

已实现会议室预约后端、兼容接口的流式 LLM 和原生 LiveKit Soniox ASR / TTS 工厂；ASR 可通过本地音频文件独立流式回放测试，TTS 可通过文本增量输入合成 WAV。现已接入原生 LiveKit AgentSession、预约工具和 Silero VAD，提供本地麦克风 console 与无音频文本入口；前端尚未实现。当前进度见下方记录。工具与确认方案以第 19 节为准；会话持久化与恢复以第 20 节为准。此前章节保留原方案和历史验证记录。

首版必须验证：

- ASR、LLM、TTS 分别流式，并在完整回复生成完毕前开始播放音频。
- 用户可以打断机器人；改口后不会继续播放过期回复或执行过期确认。
- 支持中英文跨轮切换与句内混合，语言切换不重建会话。
- 记录 Transcript、Session 事件、工具调用与延迟信息。
- 数据库查询与写入真实执行，操作可确认、可追踪且重试不重复写入。
- 明确区分用户、机器人、系统和工具内容。

暂不包含实际电话接入、额外降噪服务、语气控制、RAG、多用户并发优化和第二个后台 LLM Agent。首版使用耳机与浏览器基础回声消除。

## 2. 确定的技术方案

| 层次 | 方案 | 边界 |
| --- | --- | --- |
| Python | Python 3.11，uv | 使用项目虚拟环境与 uv.lock，不依赖默认 python3 版本 |
| 前端 | React/Next.js，pnpm | 参考 LiveKit 官方浏览器 starter，保留 pnpm-lock.yaml |
| 编排 | LiveKit Agents | 管理音频会话、模型插件、轮次、回复、打断和工具调用 |
| 传输 | WebRTC 与 LiveKit Server | 服务地址由部署配置提供，业务模块不依赖部署位置 |
| 远端 ASR | Soniox 实时 STT | 持续传入音频，输出临时和最终转录，保留中英文混合原文 |
| 远端 LLM | OpenAI API / OpenAI 兼容 Chat Completions 流式接口 | 配置 base_url 和 model，不在业务代码中绑定模型 |
| 远端 TTS | Soniox 实时 TTS | 增量输入回复文本，增量返回并播放音频 |
| VAD | Silero VAD | 检测语音活动，配合单一主要轮次结束策略 |
| 业务与日志存储 | SQLite | 保存预约、操作、Session、消息和事件 |
| 活跃会话状态 | 内存中的类型化对象 | 每个 Session 独立，首版不使用 Redis |
| 验证 | pytest、文本输入、录音实时回放、浏览器交互 | 业务与语音能够分别验证 |

LLM 接口支持原生流式输出。首版选择 Chat Completions 格式以满足跨服务兼容要求，而不是把流式能力与某个模型绑定。配置的模型必须支持流式文本与工具调用；更换端点时重新验证这些能力。模型特有参数仅在适配层按能力传递，不将思考过程或工具参数作为回复朗读。

ASR/TTS 使用各自服务的原生流式协议和 LiveKit 插件，不要求它们兼容 OpenAI 文本接口。

## 3. 远端与本地方案的解耦

ASR、LLM、TTS 分别通过配置选择 provider，三者可以独立替换。首版实现远端组合；本地组合保留同样的业务、日志和验收要求，不在当前计划中确定本地模型或硬件规格。

- provider 工厂集中创建 LiveKit 已有插件，优先复用其接口。
- LLM 的 model、base_url 与密钥引用从配置加载。
- ASR/TTS 的模型、声音、端点和能力参数从配置加载。
- 本地适配器后续实现时不得改变业务工具契约与日志角色定义。
- 原生语音模型对照实验不属于首版实现范围。

模块解耦不等于微服务拆分。首版采用一个 Python 业务进程内的模块边界，工具直接调用业务服务；音频媒体仍由 LiveKit Server 承载。

## 4. 模块与职责

| 模块 | 职责 | 独立验证方式 |
| --- | --- | --- |
| 配置加载 | 加载公开配置、环境变量和密钥，检查必要能力与参数 | 无密钥、缺少模型、非法配置的启动校验 |
| provider 工厂 | 创建 ASR、LLM、TTS 插件，处理供应商参数 | 各模型独立流式测试 |
| voice/session | 会话生命周期、音频输入输出、轮次与打断 | 浏览器和录音回放 |
| conversation | 对话规则、澄清、回复语言偏好、当前待确认操作 | 文本 Agent 场景 |
| tools | 将工具参数转换为业务服务调用，将结果返回模型 | 结构化工具请求 |
| domain | 可用时段、预约、取消、确认绑定、幂等与操作状态 | 不依赖 LLM 的业务测试 |
| storage | SQLite 表、事务、唯一约束与查询 | 临时数据库测试 |
| observability | 将框架事件转换为统一日志，记录消息、操作与延迟 | 事件重放、去重与关联检查 |
| frontend | 麦克风、播放、角色字幕、连接与会话状态 | 浏览器交互与打断验证 |

业务服务不导入语音或模型 SDK；工具层不直接拼接 SQL；日志写入不应阻塞实时音频处理。日志故障需要可见地报告，不得静默吞掉。

## 5. Streaming 与轮次规则

链路为：浏览器音频 → VAD / ASR → 会话编排 → LLM → 文本分段 / TTS → 浏览器播放。

- ASR 在用户仍说话时提供临时字幕。临时文本是可修订状态，不立即触发业务操作。
- ASR 最终文本与轮次结束是两个概念；结合所选轮次策略形成完整用户输入。
- 首版不启用投机生成，不对每次临时转录更新调用 LLM。
- LLM 内容增量用于字幕与 TTS；工具参数增量必须拼接完整并校验后执行。
- TTS 在完整回复生成前接收文本片段并返回音频，不采用完整回复生成后才下载音频的方式。
- 分段策略要兼顾首音频延迟与读音连贯性，不逐个 token 建立独立合成请求。
- 麦克风在机器人播放期间继续监听，不能用关闭输入来规避打断。
- 首版使用一种主要轮次结束策略，避免重复触发回复。

## 6. 多语言与回复偏好

仅维护会话字段 `preferred_response_language`，不维护业务级 `detected_language` 或为整轮输入指定单一语言。

- ASR 保留中英混合原文，关闭不必要的翻译。
- provider 内部的自动识别不等于应用必须保存语言标签；标签不作为会话路由或业务操作条件。
- 用户显式要求某种回复语言时更新偏好。
- 未设置偏好时，机器人按当前用户表达自然回复；无需先给整轮输入分类。
- 单个外语词、产品名或地址不触发会话重置，也不自动覆盖显式偏好。
- TTS 必需的主要语言参数由回复策略和待合成文本确定，参数处理留在适配层。
- 测试包含跨轮切换、句内混合和明确要求改变回复语言。

界面、诊断日志、错误信息和代码注释使用英文。语音对话及 Transcript 按用户所用语言与显式回复偏好保留多语言内容。

## 7. 打断、改口与操作一致性

回复与业务操作使用独立标识和生命周期：`response_id` 表示生成与播放，`operation_id` 表示业务执行。

- 用户打断时中止或废弃旧回复生成与合成，清理未播放音频。
- 旧响应的延迟片段不得在新一轮开始后继续播放。
- 上下文记录被打断状态，不能将完整生成文本视为完整播出文本。
- 中止播报不等于取消预约或回滚已提交事务。
- 用户要求取消或修改时，先检查业务状态，再执行对应业务流程。
- 用户更改待确认参数时使旧确认失效，新参数对应新的操作版本。
- 确认绑定具体操作与参数版本，不能只维护一个全局 confirmed 布尔值。
- 工具结果超时可能意味着已提交成功；先查询 operation_id，再决定是否重试。
- 已提交操作的结果仍需持久化；是否播报由当前回复状态决定。

## 8. 业务与存储契约

会议室工具包含查询可用时段、准备预约、确认预约、查询预约和取消预约。使用固定 demo 用户，由程序注入身份。

预约流程：查询 → 选择与澄清 → 准备待确认操作 → 复述具体时间和会议室 → 用户确认 → 事务执行 → 根据结果回复。

- 时间解释使用 Asia/Shanghai；日志墙钟时间采用带时区的 UTC 时间。
- 不明确的日期、时间或会议室需要澄清。
- 准备操作不直接创建正式预约。
- 写操作采用稳定的 operation_id、事务和唯一约束，重复请求返回既有结果。
- 操作状态区分待确认、执行中、成功、失败、结果未知和失效。
- 正式预约结果、操作结果与审计信息能够关联。
- 模拟数据初始化幂等，不在重复启动时追加重复时段或用户。

存储实体包含 slots、bookings、operations、sessions、messages 和 events。具体 SQL 字段在对应模块开发时确定，保持上述语义约束。

## 9. Transcript 与 Session 日志

日志从基础模块阶段建立，并贯穿所有验证阶段，不单独推迟到完整链路完成之后。

- `user` 来自麦克风 ASR 或显式用户文本输入。
- `assistant` 来自回复链路。
- `tool` 来自工具结果，`system` 来自系统规则。
- 用户输入和机器人输出不混成一条音轨后送给 ASR；不使用声纹推断逻辑角色。
- 临时字幕按 utterance_id 更新，最终消息按稳定 message_id 写入或更新。
- 同一语义用户消息不得因 ASR 事件和会话事件而重复入库。
- 事件使用 event_id 去重；保留修订时显式记录 revision 与时间戳。
- 记录 session_id、turn_id、response_id、operation_id 和工具调用标识，以支持关联。
- 区分 generated_text、打断状态和播放时长。无法可靠对齐时，不声称得到精确 spoken_text。
- 不记录 API KEY、认证头或完整环境变量。

延迟观测包含用户语音结束、ASR 最终结果、LLM 首内容、TTS 首音频和客户端播放开始。服务端耗时使用单调时钟；客户端时间单独记录，未做时钟同步前不直接计算跨端时间差。

## 10. 配置与密钥管理

公开配置集中到 `config/`，按远端与本地方案组织，包含 provider、model、base_url、声音、语言提示、回复策略、轮次参数、超时、SQLite 路径、日志选项与业务时区。配置不包含真实密钥。

- 密钥来自仓库根目录 `.env.local` 或进程环境变量。
- 进程环境变量优先于 `.env.local`；Python 显式加载该文件，不依赖当前工作目录隐式发现。
- provider 配置只引用密钥环境变量名。
- Soniox 密钥使用 SONIOX_API_KEY，OpenAI 密钥使用 OPENAI_API_KEY；兼容端点允许配置其他密钥变量名。
- LiveKit 连接地址为公开配置；API key、API secret 等认证配置由服务端环境提供。
- 前端只获得公开配置和短期连接 token，不获得供应商密钥或 LiveKit API secret。
- 不将服务端密钥放入 NEXT_PUBLIC_* 变量。
- 实现阶段创建仅含占位符的环境变量示例，并将实际 `.env.local`、数据库、日志与录音加入忽略规则。
- `.env.local` 不在当前文档阶段创建；README 不展示真实密钥。
- Python 与前端依赖分别锁定，不默认升级依赖。

## 11. 开发步骤与阶段验收

| 阶段 | 开发内容 | 必须通过的验证 |
| --- | --- | --- |
| A：项目与业务基础 | uv/pnpm 项目、配置加载、日志基础、SQLite、业务服务 | 缺配置报告明确；种子数据和写操作幂等；确认版本与事务正确 |
| B：文本对话 | 兼容 LLM 流式接口与工具接入 | 首文本增量可见；中英混合、回复偏好和改口生效；工具结果与角色日志正确 |
| C：语音组件 | 独立 ASR/TTS 流式与 VAD 验证 | ASR 临时结果和混合语言正确；TTS 增量输入输出；停止合成与播放有效；各组件事件可追踪 |
| D：完整浏览器链路 | WebRTC、AgentSession、语音预约与字幕 | 三段流式成立；可打断；跨轮与句内切换不丢状态；过期回复不复活；角色和打断日志正确 |
| E：完整场景回归 | 故障注入与端到端用例 | 确认期间改口、执行期间插话、提交成功后超时、重复请求、断连均保持可解释的业务状态 |

打断、改口、多语言和日志是模块开发与完整链路的持续要求。阶段 E 补充整体回归，不代表前面阶段可以忽略这些要求。

本地方案在远端基线完成后开发，复用相同验收场景，再分别替换 ASR、LLM、TTS。当前不选定本地模型。

## 19. SQL/edit 工具与通用 Agent 调整（2026-10-07）

本节替代此前预约 Agent 工具与确认策略。用户要求放弃原来的固定业务工具和确认约束；不采用上轮讨论的 Workspace、多种查询工具或统一草案方案。

- 新增独立 ConversationAgent 基类；BookingAgent 继承后只增加 query 和 edit 两个业务工具。通用基类提供原有流式节点、轮次检查、语言偏好、日志及 escalate_reasoning。
- query 接受一条 SQL，支持联表、聚合、CTE、跨日期和 schema 查询。SQLite 只读连接和 authorizer 拒绝写入及连接控制；config/booking_agent.toml 设置行数、VM 步数和耗时上限。
- edit 用 action（add/delete/update）、房间、开始和结束时间，以及可选替换值直接编辑预约。可创建未预设的区间；删除使用 cancelled 状态保留历史；修改原子更新并保留 booking ID。不要求 operation ID/version、固定确认命令或仅操作当前用户记录。
- 确认由语言 Agent 根据上下文完成：先说明具体变更、询问，后续用户自然同意后调用 edit。没有额外确认工具或确定性确认授权机制；prompt 策略不保证任意模型输出都会遵守。业务层保留时间格式、有效区间、活动预约冲突、事务、审计和重试幂等检查。
- 同轮相同规范化参数的 edit 使用稳定 host request key 重放结果；不同用户轮次为新请求。已开始的数据库事务不随语音取消回滚；过期调用在执行前拒绝。
- 预约 prompt 存放在 config/booking_prompt.md，职责为本地系统管理助手。查询不强制指定单个日期，应主动搜索并区分未配置、占用和无匹配。
- 默认时区改为 Asia/Singapore；无 offset 的 edit 时间按该时区解析，存储继续使用 UTC。
- 默认模型维持 thinking disabled。config/llm.toml 新增可替换 reasoning profile；当前同模型 thinking enabled、high 强度、8192 token、60 秒超时。escalate_reasoning 先短句提示，再执行一次不带工具的流式分析，返回结论供默认模型继续查询或编辑；每轮最多一次，结束、失败、打断都不更改默认模型设置。
- DeepSeek 思考工具链需要回传 reasoning_content；当前原生插件未提供该完整回传，因此升级采用隔离的无工具分析请求，不在本轮扩展供应商协议或框架。
- 原 SQLite schema、业务 CLI 和旧工具单元测试保留兼容；当前 Agent 不暴露旧七工具。数据库权限、认证、Workspace 及其他 provider 解耦本轮不扩展。
- 用户已确认使用手动启动的本地 livekit-server --dev，不使用 Cloud。用户前端范围确定为连接状态、麦克风开关、角色区分的 transcript、播放/打断、预约结果与回复语言；本轮不实现前端。
- 自动与真实 API 验证结果见 [实时语音验证指南](实时语音验证指南.md)。


## 20. 独立会话服务与日志调整（2026-10-07）

- 新增独立 SQLite SessionStore，记录 session、attempts、请求幂等键、原生 history 和 typed userdata，不依赖预约模块。通过 factory 组合 BookingAgent 或无业务 ConversationAgent。
- 正常结束后的恢复在本阶段实现：沿用 session_id、新建 attempt_id，恢复原生上下文与回复语言偏好，不重放工具调用。不允许恢复活动、异常、取消或租约过期的会话。
- 文本入口增加 /session 当前状态、列表、历史、结束、新建和恢复指令；检查命令无需模型密钥。正常 EOF、/quit 与 /session end 完成最终检查点；Ctrl+C 视为异常。
- 会话历史统一使用 session.history 与 ChatContext 序列化；userdata 采用显式 dataclass。不再周期性重写全量 JSON、复制业务审计或保存每次临时 ASR 修订。
- metrics、诊断事件和可选 OpenTelemetry tracing 使用另一个 SQLite 数据库，具有队列、条数和时间保留限制。模型上下文限制与历史归档分开；单次运行有时间上限。
- 使用现有 aiohttp 实现本地会话／token API，签发具名 dispatch token，绑定统一 session/attempt/room，区分内部与浏览器服务地址。结束先等待 worker 正常关闭并保存，再清理房间。
- 没有新增或升级依赖，没有开发前端、Docker、业务安全或自然语言策略修正，没有执行真实麦克风与浏览器测试。
