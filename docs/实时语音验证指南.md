# 实时语音与预约 Agent 验证指南

## 1. 已实现范围

原生 LiveKit AgentSession 将现有流式 Soniox ASR、DeepSeek LLM、预约工具和 Soniox TTS 连接起来。Soniox endpointing 决定用户轮次结束，Silero CPU VAD 检测语音活动并触发打断。会话关闭预生成与误打断后的自动恢复，避免旧回复重新播放。

无需先开发前端：本地麦克风入口复用锁定版本 SDK 自带的 Python console；无音频文本入口运行同一个 BookingAgent 和工具。另有房间 worker，供后续 WebRTC 客户端接入。这些入口仍会调用收费模型 API。

代码边界如下：

| 模块 | 职责 |
| --- | --- |
| voice/config.py、config/voice.toml | 会话、日志周期和 VAD 公共参数 |
| voice/session.py | provider 组合、原生会话与资源生命周期 |
| voice/agent.py | 原生工具包装、轮次状态、提案复述及写操作授权 |
| voice/journal.py | 消息去重、事件及业务结果、原子快照 |
| voice/text.py | 无前端标准输入对话 |
| voice/worker.py | 本地麦克风 console、具名房间 worker |
| tools、domain、storage | 原有工具、确定性业务服务与 SQLite |

## 2. 准备

在项目根目录执行：

```bash
uv sync --locked --python 3.11
PYTHONPATH=backend uv run --locked python -m opentalk seed --date 2030-01-02
PYTHONPATH=backend uv run --locked python -m opentalk available --date 2030-01-02
```

日期应晚于实际测试日期。种子使用 config/backend.toml 的业务时区、房间与时间段。请先检查可用结果：此前测试若已占用某时间段，需要取消或选择其他可用时段。

密钥从进程环境或根目录 .env.local 读取，环境变量优先：

- 文本入口仅需 DEEPSEEK_API_KEY，使用 config/llm.toml 的官方端点与 deepseek-flash 配置。
- 麦克风入口另需 SONIOX_API_KEY，复用 config/asr.toml 和 config/tts.toml。
- 房间 worker 另需 LIVEKIT_API_KEY、LIVEKIT_API_SECRET 和可访问的 LiveKit Server；地址在 config/voice.toml，可用 LIVEKIT_URL 覆盖。

本轮添加 Silero 插件及所需 ONNX Runtime、FlatBuffers，未升级原有依赖。Silero 模型已包含在插件中，本轮验证不需要额外下载。

## 3. 无音频文本入口

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.voice.text
```

逐轮输入，等待 Assistant 回复后再继续。例如：

1. “帮我查一下 2030 年 1 月 2 日 Room A 上午九点是否可用。”
2. “选九点，帮我准备预约。”
3. 等待包含房间、日期、时间、时区的完整复述；可以先输入“改成十点”，等待新方案复述。
4. 单独输入“确认预约”或 `confirm booking`。
5. 核对工具确实成功，再单独输入“取消预约”或 `cancel booking`。
6. `/quit` 或 EOF 退出，Ctrl+C 也会关闭资源并保存日志。

自然语言查询和选择由 LLM 决定是否调用工具，不保证固定措辞或每次都正确选择；请核对返回方案。文本 CLI 支持 Linux/WSL 标准输入，也可用管道按行传入。它不启动 ASR/TTS、音频设备或 LiveKit Server，不能用来验证声学打断。

## 4. 无前端麦克风对话

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.voice.worker console --list-devices
PYTHONPATH=backend uv run --locked python -m opentalk.voice.worker console
```

需要指定设备时：

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.voice.worker console --input-device "DEVICE_NAME" --output-device "DEVICE_NAME"
```

将 DEVICE_NAME 替换为设备编号或名称。当前锁定 SDK 仍提供 Python console，帮助输出标注 deprecated；此处复用现有可用入口，没有引入额外 Go CLI。它与 LiveKit 的浏览器 Agent Console 是不同入口，参见[官方说明](https://docs.livekit.io/testing/agent-console/)。

本地 console 不需要 LiveKit Server。它需要 PortAudio 系统库，以及运行 Python 的环境能访问麦克风与播放设备。当前开发环境未找到 PortAudio，因此未实际打开麦克风。Ubuntu/WSL 可先安装 libportaudio2，再用 --list-devices 检查；WSL 下还要确认音频设备确实可用。建议用耳机验证，当前未加入降噪与回声消除。

运行后依次验证：

| 场景 | 操作与观察 |
| --- | --- |
| 流式对话 | 使用较长、多句回复，观察开始播报与响应过程；检查日志中的原生消息指标、usage 和回复完成事件 |
| 预约 | 查询、选择、听完准确复述、下一轮确认；检查实际 SQLite 与业务事件 |
| 改口 | 复述后要求另一个时间；确认新方案，旧 proposal 应失效 |
| 打断回复 | Agent 播放长回复期间持续说新需求；旧播放应停止，新转录完成后回答新需求 |
| 打断复述 | 提案复述途中打断，然后说确认预约；应拒绝确认，重新请求准备/复述方案后再确认 |
| 混合语言 | 例如“帮我 check Room A，January second，上午 ten”；保留原文，不生成独立 detected_language |
| 回复偏好 | 单独说“请用英语回复”或“请用中文回复”，再说混合需求；明确偏好保持，后续 TTS 使用对应主要语言 |
| 取消 | 最近成功预约或查询预约后，单独说取消预约；核对 cancelled 状态 |

默认 min_interruption_duration 为 0.3 秒，配置的是 VAD 触发阈值，不是承诺的端到端打断延迟。ASR endpointing、供应商响应、文本分句和音频输出都会影响实际延迟。轮次和打断的职责采用[LiveKit 的 STT/VAD 组合机制](https://docs.livekit.io/agents/logic/turns/)。

## 5. 确认与取消的当前规则

- 支持独立确认命令：“确认预约”“确认预订”“confirm booking”“confirm reservation”。允许大小写、常见末尾标点与空白差异。
- 支持独立取消命令：“取消预约”“取消预订”“cancel booking”“cancel reservation”，目标为本会话最近成功预约或成功查询过的预约。
- 确认只授权当前 operation ID/version，且准确复述必须完整结束。被打断或失败的复述不授权。隐式 yes、引文、包含修改要求的确认句不授权。
- 固定提案复述和诊断使用英文；LLM 自然回复可多语言。中文确认命令仍有效。回复偏好仅支持上述明确命令，不实现任意自然语言偏好解析。
- 模型不能调用授权方法自行获得权限。实际业务服务仍校验所有权、版本、有效期、冲突与幂等。
- 尚未开始的旧轮次操作被拒绝；已经开始的事务会保留真实结果，不因停止播报回滚。若不知道执行结果，通过 get_operation 恢复，不能把没有听到成功回复等同于没有执行。

## 6. 日志与状态检查

日志路径为 logs/voice/<session_id>.json，Git 已忽略。worker/console 默认每秒保存一次；文本入口每轮保存；正常关闭和错误退出的资源清理会再次保存。以原子替换方式更新同一文件，不重复追加整轮内容。日志写入失败会导致运行失败，不静默丢失。

- messages：按原生 message ID 更新的 user/assistant 消息、原生时间、metrics 和 interrupted 标记。
- events：带稳定事件 ID、UTC 时间与会话内单调耗时的 ASR 临时/最终转录、轮次、状态、回复、工具、usage 及错误类型。
- responses：按 speech handle ID 记录生成文本和 completed/interrupted/failed 状态。generated_text 不代表精确已播报文本。
- operation_events：当前用户/会话对应的 SQLite 业务审计快照。

工具调用及结果位于独立事件，不会冒充 user 或 assistant 消息；ASR 最终转录不会额外复制成第二条用户消息。日志不记录 API 密钥或认证 payload，不保存音频。日志指标来自 SDK；尚未实现前端播放时间戳或跨端时钟同步。

可另开终端检查业务状态：

```bash
PYTHONPATH=backend uv run --locked python -m opentalk booking BOOKING_ID
PYTHONPATH=backend uv run --locked python -m opentalk operation OPERATION_ID
PYTHONPATH=backend uv run --locked python -m opentalk events
```

## 7. 房间 worker 与后续前端

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.voice.worker dev
PYTHONPATH=backend uv run --locked python -m opentalk.voice.worker start
```

选择 dev 或 start 之一运行；dev 支持开发重载。默认 agent_name 为 opentalk-booking。由于使用具名 worker，客户端/调度端必须显式 dispatch 该名字。尚未添加前端、token 服务或安装 LiveKit Server；无需先配置这些服务来使用本地 console。

## 8. 自动化验证结果

```bash
uv run --locked pytest -q

```

2026-10-07 完整离线测试：64 passed、3 skipped；新实时会话相关测试 16 项。三项真实付费 LLM 测试依照原有规则默认跳过。

测试使用真实 AgentSession、原生工具执行与 SQLite，LLM/STT/TTS 和播放设备用流式测试替身。覆盖预约/改口/确认/取消、错误确认及版本、偏好保持、音频链路、程序化打断、旧音频停止、复述打断后拒绝授权、旧工具拒绝、已开始事务取消时保留结果、取消授权期间改口、日志去重与文本 CLI 管道输入。Silero 模型同时执行了真实本地静音推理。

用户此前已报告单独 ASR/TTS 手动测试通过；本轮没有 Soniox 凭据和可用麦克风环境，未执行真实完整语音会话。模拟测试通过不等于真实声学 barge-in、发音、准确率与远端延迟已经验证。
