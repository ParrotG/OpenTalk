# OpenTalk 开发计划

## 当前基线

当前分支保留通用浏览器语音助手，原预约业务已移除。支持文字／语音切换、流式字幕、语音打断、正常结束后的会话恢复和 Docker 本地部署。后续业务通过 Agent factory 接入；本次不实现新的业务或 RAG。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| agents/base.py | 通用对话、回复语言偏好、轮次校验和一次性推理升级 |
| voice/factories.py | Agent 注册与业务适配边界，当前仅 conversation |
| voice/session.py | 原生 AgentSession、provider、VAD 和生命周期 |
| voice/room_control.py | 文字／语音 RPC、音频输出切换和断连处理 |
| sessions/ | 会话索引、attempt、历史、租约、控制 API 和有界遥测 |
| asr/、llm/、tts/ | 独立模型工厂及组件验证入口 |
| frontend/ | 浏览器媒体、字幕、历史和同源 API 代理 |

## 已保留能力与验收要求

- Python 3.11／uv 和 Node.js 24／pnpm，沿用锁文件，不升级依赖。
- Soniox ASR、OpenAI 兼容 LLM、Soniox TTS 分别流式；模型替换需要验证插件契约。
- ASR 临时结果用于展示，最终轮次才触发回复；关闭投机生成。
- Silero CPU VAD 触发打断，不继续播放旧响应；已开始的工具执行与播报生命周期分离。
- 同一连接保留中英文混合内容，明确语言偏好保存到 userdata。
- 会话和遥测分别持久化，稳定消息／事件 ID 去重；用户历史不受遥测保留上限影响。
- 正常完成才能恢复；恢复沿用 session ID，新建 attempt 和房间，不重放工具。
- 网页文字模式不合成音频；关闭语音不重启原 LLM 回复。
- provider 凭据只在服务端读取，不放入 NEXT_PUBLIC_*。

## 后续业务接入

实现独立业务服务，再通过 ConversationAgent 子类或工具适配层注册能力，并在 voice/factories.py 增加 Agent key。业务权限、事务和幂等由新服务负责；会话历史不作为写操作授权。业务数据由新服务管理，不混入会话或遥测数据库。

现有旧业务会话保留为历史，不迁移到 conversation，也不恢复其已删除的工具。新会话使用 conversation。

## 验证顺序

1. 运行无付费后端测试，验证 provider 协议、轮次、取消和会话持久化。
2. 运行前端类型检查和独立 UI 测试。
3. 使用 OPENTALK_TEST_RTC=1 检查原生 WebRTC／RoomIO。
4. 使用独立 Compose 验证栈检查调度、媒体、自动恢复和持久化。
5. 显式开启付费模型测试，再人工检查真人麦克风、回声和主观听感。

各组件指南中的历史日期和测试数量只代表当时版本。当前分支以实际运行结果为准。
