# 开发与验证参考

本文保留从 README 移出的组件命令、实现约束和环境排错信息。整体架构与快速启动见 [README](../README.md)，分阶段设计与历史验收记录见 [开发计划](开发计划.md) 和各验证指南。下列命令默认从项目根目录执行。

## 1. 依赖与配置约定

- 后端使用 Python 3.11、uv 和 `uv.lock`；前端使用 Node.js 24、pnpm 10.13.1 和 `frontend/pnpm-lock.yaml`。使用锁定安装，不默认升级依赖。
- 代码注释、UI 标签、诊断与错误信息使用英文；多语言对话及转录保留原文。
- 业务规则与语音框架、模型 SDK 分开。增加服务通过 `voice/factories.py` 中的适配层完成，不让会话存储导入业务 Repository。
- JSON／JSONL 与数据库记录使用稳定 ID，重试更新已有记录；确需保留多次采样时，增加明确的时间戳或版本。
- 中断、意图变化、多语言、超时和关闭资源应纳入组件验收。

```bash
uv sync --locked --python 3.11
```

Python 显式加载根目录 `.env.local`，进程环境变量优先。相对数据库路径按项目根目录解析，不随运行目录变化。模型凭据、数据库、转录与录音均不提交到仓库。

## 2. 独立 LLM 验证

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.llm.smoke
uv run --locked pytest tests/test_llm_live.py --live-llm -q
```

两者都会调用实际付费模型；后者默认跳过，必须显式传入 `--live-llm`。流式 smoke 使用原生 `LLM.chat()`，检查非空文本分片，报告首个内容时间、总时间、输出和用量，不修改预约数据。

当前 `config/llm.toml` 使用 `deepseek-flash`，日常请求关闭 thinking；默认输出上限 1024 token，超时 30 秒。模型 ID、供应商选项及密钥变量名由配置决定。替换端点时检查流式输出、工具调用、usage 与 `extra_body` 的兼容性。

`[reasoning]` 用于一次独立的高强度请求，当前覆盖为 8192 token、60 秒、thinking enabled 与 high reasoning effort。`escalate_reasoning` 每个用户轮次最多执行一次，先通过原生 session 发出简短回应，再将自包含任务交给无工具的分析请求；只返回答案内容，不返回内部 reasoning trace。原 Agent 获得结论后继续使用默认 provider 和业务工具。

将分析请求与普通工具循环分开，也避免把供应商特定的 reasoning-history 字段直接带入通用的原生工具循环。切换供应商时，应同时检查其思考模式的历史要求与请求参数；可调整 reasoning profile，或删除该配置以禁用升级。相关供应商说明见 [DeepSeek 文档](https://api-docs.deepseek.com/)。

## 3. 独立 ASR 文件回放

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.asr.replay recordings/demo.wav --output logs/asr-demo.json
PYTHONPATH=backend uv run --locked python -m opentalk.asr.replay --help
uv run --locked pytest tests/test_asr_offline.py -q
```

回放只需要 `SONIOX_API_KEY`，不需要 LLM、TTS、LiveKit Server 或麦克风。输入可为已安装 PyAV 支持的 WAV／MP3／M4A 等格式；程序增量解码、混为单声道 PCM16，并重采样，不要求外部 `ffmpeg` 命令。音频按原时长以 20 ms 帧发送，而非一次性上传。

当前使用 `stt-rt-v5`、16 kHz、中英文非严格 language hints 和 1500 ms 最大 endpoint delay，不开启翻译、语言标签或说话人分离。终端即时输出 JSON 行事件，最后输出汇总；报告记录临时修订、最终 user 消息、usage 和相对回放起点的时间。

锁定的 Soniox 插件不会在 `end_input()` 时立即终止远端会话。文件结束后继续发送 3 秒静音，等待 usage 覆盖已发送音频、临时识别完成最终化，然后关闭流。静音也属于付费输入；其后的 drain 默认最多等待 15 秒。未最终化、缺少处理确认或没有最终语音结果会明确失败。

这是有界的实时流回放，不是异步文件 API，也不声称收到服务器 `finished` 确认。短录音可能只有最终结果，观察临时修订应使用较长输入。

省略 `--output` 时生成 `logs/asr-<session_id>.json`；指定输出时原子替换，避免重复追加整个报告。Ctrl+C 关闭资源并记录 cancelled。完整场景与报告字段见 [ASR 验证指南](ASR验证指南.md)。

## 4. 独立 TTS 文本流

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.tts.smoke --text "会议室 A 明天上午十点可用。Please confirm the date and time before booking." --output recordings/tts-demo.wav --report logs/tts-demo.json
PYTHONPATH=backend uv run --locked python -m opentalk.tts.smoke --text-file recordings/tts-input.txt --language en --output recordings/tts-en.wav --report logs/tts-en.json
PYTHONPATH=backend uv run --locked python -m opentalk.tts.smoke --help
uv run --locked pytest tests/test_tts_offline.py -q
```

TTS 与 ASR 共用 `SONIOX_API_KEY`，不需要其他模型、LiveKit Server 或音频设备。使用原生 Soniox 插件的 `push_text()` 接口提交增量文本，插件进行句子缓冲与 WebSocket 合成；程序边接收 PCM16 音频边写文件，成功后发布 WAV。测试入口不实时播放，完成后自行使用播放器试听。

当前模型为 `tts-rt-v2`，音色 `Maya`，主语言 `zh`，采样率 24 kHz、单声道、速度 1.0。测试默认每 150 ms 提交 12 个字符，整个测试超时 120 秒。多句长文本适合观察 `audio_before_input_end`；短输入在首段音频产生前可能已提交完毕，这本身不代表不支持流式。

`--language` 设置整体发音的主语言，不删除外语词句。provider 支持在同一实例上通过原生 `update_options(language=...)` 调整后续流。

报告包含提交文本、文本／音频事件、原生 request／segment ID、时间、帧数和音频时长，不将接收到音频等同于用户已经听到。省略路径时使用 `recordings/tts-<session_id>.wav` 和 `logs/tts-<session_id>.json`。

成功输出与报告原子替换；失败不覆盖已有成功 WAV。Ctrl+C 或 `--cancel-after 2` 保留已接收音频为 `<output-stem>.partial.wav`，报告标为 cancelled，退出码为 130。具体试听、异常与取消用例见 [TTS 验证指南](TTS验证指南.md)。

## 5. 原生文本与本地音频入口

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.voice.text
PYTHONPATH=backend uv run --locked python -m opentalk.voice.text --agent conversation
```

文本入口使用与语音相同的 AgentSession 和工具执行机制，但不启动 ASR／TTS／VAD，不检查声学打断。启动后可先使用会话命令，首次普通输入或显式新建／恢复才启动 Agent。

```text
/session
/session list 20
/session show SESSION_ID
/session history SESSION_ID
/session new
/session end
/session resume SESSION_ID
/session help
/quit
```

`/session end`、`/quit` 和正常 EOF 会正常保存并结束；Ctrl+C 或异常关闭按 failed 处理。`/session resume` 仅接受 completed。完整状态与控制 API 见 [会话管理验证指南](会话管理验证指南.md)。

`请用英语回复`／`please reply in English`、`请用中文回复`／`please reply in Chinese` 可以设置显式回复偏好，后续 TTS 主语言随偏好调整。这不是任意语言指令的通用解析器，多语言内容仍由实际模型理解。

需要直接使用本机音频设备时，可运行：

```bash
PYTHONPATH=backend uv run --locked python -m opentalk.voice.worker console --list-devices
PYTHONPATH=backend uv run --locked python -m opentalk.voice.worker console
```

console 需要 PortAudio 系统库与可访问的录放音设备。锁定 SDK 仍提供 Python console，但将其标记为 deprecated。此 worker 配置会初始化 LiveKitAPI 客户端，因此 console 也需要 LiveKit API key／secret，即使不连接房间；纯文本入口不需要。网页与 Docker 语音不需要把本机音频设备映射进 Python 或容器。

房间 worker 的 `dev` 支持开发运行，`start` 用于无开发重载的运行方式；默认注册名为 `opentalk-booking`，客户端需显式 dispatch 相同名称。会话 API 已负责网页的 token 和命名调度，不需要前端自行编写业务调度逻辑。原生网页启动见 [网页语音验证指南](网页语音验证指南.md)。

## 6. 工具、事务与存储边界

`query` 仅允许一个只读语句。SQLite authorizer 拒绝写入、ATTACH、PRAGMA、事务控制和扩展加载；默认最多返回 200 行，执行步数预算 100,000，耗时预算 2 秒，截断结果明确标记。配置位于 `config/booking_agent.toml`。

`edit` 参数描述新增／取消／调整、原资源与起止时间，以及可选的新资源、新区间。用户 UID 来自可信运行配置，工具传入不同 UID 不能改写身份。修改必须通过所有权、时间及并发容量校验；同一用户不能在同一资源上重叠预约，不同资源可以同时预约。

请求键绑定用户轮次和原生 tool call，重复执行返回原结果，相同键更换参数会冲突。失败结果同样保存；更改条件后重试应成为新请求，而不是用相同键覆写旧结果。业务变化与 operation 结果在同一事务提交。开始写入后即使语音被取消也等待完成，未开始的过时调用被拒绝。

自然语言确认由系统说明约束模型行为，没有固定确认词或独立授权凭证。测试要核对数据库所有权和结果，不能把“模型说已完成”作为成功依据。业务用例见 [BookingService 自然语言测试用例](BookingService自然语言测试用例.md)。

会话历史使用 `ChatContext.to_dict()`／`from_dict()`，排除音频、图片、指标和配置事件。恢复后的 Agent 上下文含历史，SDK 本次运行的 `session.history` 记录当前 attempt；数据库按原生 ID 合并，不修改 SDK 私有属性。

会话默认每 5 秒心跳，活动租约 60 秒，未连接的 pending 分配在 900 秒后过期，单次运行最长一小时。上下文最多 120 条；诊断待处理队列 512 条，遥测数据库最多 10,000 条及 7 天。配置可调整。历史保留与诊断保留是不同策略。

指标来自插件 `metrics_collected`、原生消息 metrics 和 `session.usage`，不依赖已弃用的 session 级 metrics 事件。可选 tracing 使用官方 tracer provider，禁用内容采集，批量导出到同一个有界遥测库。房间 `JobContext` 可生成报告，但文本入口没有这一对象，当前不额外复制完整报告。旧 `logs/voice` JSON 不自动导入。

## 7. 管理员与隔离数据

```bash
PYTHONPATH=backend uv run --locked python -m opentalk admin init --start-date 2030-01-02 --days 7 --fixture config/booking_demo.json
PYTHONPATH=backend uv run --locked python -m opentalk admin inspect --table users
PYTHONPATH=backend uv run --locked python -m opentalk admin inspect --table resources
PYTHONPATH=backend uv run --locked python -m opentalk admin inspect --table reservations --limit 200
PYTHONPATH=backend uv run --locked python -m opentalk admin check
PYTHONPATH=backend uv run --locked python -m opentalk --database /tmp/opentalk-case.sqlite3 admin init
```

显式日期应晚于测试当天。默认 fixture 定义 Alice、Bob、Chen、Dina 和 Room A、Room B、Desk Zone、Projector 1，容量分别为 1、2、3、1；每天有 09:00、10:00、14:00、15:00 示例区间及部分占用。全新七天库有 112 slots、49 reservations／operations。

重复初始化不会覆盖既有预约或重新激活已取消记录；冲突样例在 `skipped` 中报告。复现测试应使用新库，不把重复初始化当作重置。

`--database` 是业务管理员命令的全局选项，放在 `admin` 前。文本 Agent 的 `--config` 可指向使用同一隔离路径的 backend 配置；`--session-config` 可另外指定会话与遥测路径。容器使用独立数据卷，相关管理、隔离项目和持久化测试见 [Docker 指南](Docker验证指南.md)。

## 8. 环境排错与验证边界

主机默认 `python3` 不一定是 3.11，使用 `uv sync --locked --python 3.11` 明确选择项目版本。Node／pnpm 同样按前端约定检查。PortAudio 仅用于本地 console，不是网页或 Docker 的运行前提。

若 uv 缓存目录无写权限，可临时指定独立目录：

```bash
UV_CACHE_DIR=/tmp/opentalk-uv-cache uv sync --locked --python 3.11
```

在开发工具的受限执行环境中，曾观察到 `asyncio.run()` 的线程池关闭停滞，包括最小的 `asyncio.to_thread()` 程序。遇到类似情况应先在普通终端复现，区分执行环境限制与应用问题；这不是必须添加到程序中的特殊处理。真实 API 验证另需网络访问。

Services 为 ok／configured 不能证明模型调用或 WebRTC 媒体已通。原生 localhost、WSL 与 Docker bridge 的 ICE 配置不同；媒体排错见 [网页指南](网页语音验证指南.md) 与 [Docker 指南](Docker验证指南.md)。

组件模拟测试验证协议处理与错误路径；真实房间测试验证调度和传输；付费模型验证理解、识别及发音；真人麦克风验证噪声、回声和实际打断体验。这些证据应分开记录，不能相互代替。各指南中的日期和测试数量属于对应阶段的历史记录，当前覆盖以仓库测试为准。
