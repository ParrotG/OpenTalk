# 实时语音验证指南

## 当前方案

原生 LiveKit AgentSession 编排 Soniox ASR、OpenAI 兼容 LLM、Soniox TTS 和 Silero CPU VAD。ASR endpointing 决定轮次结束，VAD 触发打断；关闭投机生成和误打断自动恢复。当前只提供通用 ConversationAgent，不加载业务数据库。

系统提示要求简短自然口语，不使用表格、Markdown、emoji 或代码块。配置、密钥与独立组件入口见 README 和开发与验证参考。

## 入口

```bash
uv sync --locked --python 3.11
PYTHONPATH=backend uv run --locked python -m opentalk.voice.text
```

文本入口仅需要 LLM 凭据；会话管理命令无需模型调用。浏览器运行需分别启动 LiveKit、会话 API、worker 和前端，见网页语音验证指南。

```bash
livekit-server --config config/livekit-local.yaml
PYTHONPATH=backend uv run --locked python -m opentalk.sessions.api
PYTHONPATH=backend uv run --locked python -m opentalk.voice.worker dev --no-reload --log-level info
```

默认 worker 注册名为 opentalk-conversation。console 可使用本机麦克风，但需要 PortAudio、音频设备及 LiveKit key／secret；锁定 SDK 将该 console 标注为 deprecated。网页和 Docker 不需要 PortAudio。

## 手动场景

1. 输入中文、英文以及句内混合内容，检查字幕和回复。
2. 单独输入“请用英语回复”或“please reply in Chinese”，检查后续偏好。
3. 要求多句长回答，检查全文生成结束前开始收到音频。
4. 回答播放期间说话，检查旧回复停止，新输入被处理。
5. Cancel voice 返回文字模式，检查原文本生成继续且不再播放音频。
6. 正常切换聊天或关闭页面后重新打开，检查同 session ID、新 attempt 恢复。
7. 异常断连后检查 failed 状态，确认不能恢复。

## 推理升级

escalate_reasoning(task, message?) 每轮最多一次，先提示用户，再执行独立无工具分析。只返回结论，默认 LLM 配置不改变。任务必须自包含，不能借该工具访问外部业务。

可输入“请先简短提示，再用 escalate_reasoning 比较两个已知方案”，之后发送普通消息，核对 reasoning_finished 的 active_profile 为 default。真实模型测试需显式启用。

## 日志与回归

历史与 userdata 位于 data/sessions.sqlite3；metrics、诊断及可选 traces 位于 logs/telemetry.sqlite3。临时字幕不逐次入库，历史按原生 ID 更新；不声称记录精确 spoken_text。

```bash
PYTHONPATH=backend uv run --locked pytest -q
PYTHONPATH=backend uv run --locked pytest tests/test_llm_live.py --live-llm -q
```

离线测试使用确定性模型与测试工具，验证流式协议、过期调用拒绝、已开始工作在取消后完成、音频中断和会话恢复。它们不能替代真人麦克风或实际服务商质量验收。
